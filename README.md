# PRTS 个人工作台

以《明日方舟》PRTS 的视觉语言为灵感，整理待办、笔记、文件与专注时间的个人工作台。前端使用 React、TypeScript 和 Vite，后端使用 Node.js 原生 HTTP 服务，可选接入 OpenAI 兼容的 AI 服务。

界面包含启动序列、菜单切换、弹窗和几何扫描等网页动效。它们是本项目的实现，未针对指定游戏版本逐帧校准，不承诺与原版完全一致。

## 功能

- **终端总览**：阿米娅原始游戏立绘，查看任务、最近笔记、操作动态和专注计时。素材来源与权利说明见 [图片素材记录](docs/assets.md)。
- **密码入口**：进入任何模块前验证密码，支持刷新保留会话和主动锁定，后端接口同步验证登录。
- **任务管理**：自定义分类，按分类分栏；总栏桌面每行三列，窄屏自动缩为两列或一列。支持栏内新增、编辑时换分类、完成和删除任务，以及优先级、截止日期、搜索和筛选。
- **笔记档案**：Markdown 编辑与预览、自动保存、标签、置顶和搜索。
- **文件资料**：选择或拖入文件，搜索、筛选、图片预览、下载和删除。
- **PRTS 助手**：本地规则指令、三种性格的 AI 对话，以及《明日方舟》和《明日方舟：终末地》语料检索与来源引用。
- **系统设置**：昵称、专注时长、完成提示音、动效开关、语料首次下载与更新，以及 JSON 备份导入导出。

首次使用包含示例任务和笔记；文件库初始为空。

任务分类可在「任务中枢 → 管理分类」中新增、改名或删除。分类最多 50 个，名称最多 40 字；删除分类会把任务移入「未分类」，不会删除任务。旧版任务也会保留在「未分类」，可通过编辑任务选择分类；新建示例工作台包含工作、学习、生活三个分类。分类信息随工作台 JSON 备份一并保存，旧备份可导入并自动迁移。

AI 性格、参考语料、检索作品及任务优先级使用统一的 PRTS 深色下拉面板，支持方向键、Home/End、Enter/空格选择、Esc 关闭与 Tab 离开；在手机和任务弹窗中也可使用。

## 本地开发

需要 **Node.js 22.18.0 或更高版本**及 npm。

```sh
npm install
```

直接启动即可；`.env` 是可选的部署配置。如果希望自行指定初始密码，可在首次启动前复制 `.env.example` 为 `.env` 并填写 `PRTS_PASSWORD`。没有指定时，服务会生成随机密码，并在首次启动日志输出一次：

```sh
npm run dev
```

打开 <http://127.0.0.1:5173>。该命令同时启动 Vite 前端和 `127.0.0.1:8787` 的 API 服务，前端将 `/api` 请求代理给后端。

使用自行指定或启动日志中的密码登录。不配置 AI API 密钥也可以使用任务、笔记、文件、专注计时、助手的本地指令和已同步语料的离线检索。例如：

```text
今日任务
查看笔记
搜索笔记 工作
新建任务：整理本周笔记
专注状态
```

本地指令按固定规则执行，不调用模型。

## 手机桌面应用（PWA）

使用 HTTPS 打开工作台后，可在「系统设置 → 手机桌面应用」查看安装方法。Android 浏览器支持时会显示「安装 PRTS」按钮，也可在浏览器菜单选择「安装应用」或「添加到主屏幕」。iPhone / iPad 用 Safari 打开，点按「分享 → 添加到主屏幕 → 添加」。安装后可从桌面图标以独立窗口启动，部分浏览器还支持长按图标进入任务、笔记和助手。浏览器支持范围和安装方式见 [MDN 安装说明](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing)。

PWA 继续使用同一台 VPS 和 SQLite；首次在桌面应用中打开时可能需要重新登录。已适配安全区、底部手势区域及移动端输入字号。断网时锁定工作台；重新打开会显示离线页，网络恢复后重新连接。仅缓存公开图标、安装清单和离线页，**不缓存任务、笔记、聊天、登录接口、附件、语料或游戏配图**，此版本不提供离线编辑。

联网访问时检查更新，新版本就绪后提供「更新应用」按钮；点击前先保存当前编辑，确认后刷新。也可在设置页手动「检查更新」。Service Worker 只在 `npm run build` 的生产构建中启用，`npm run dev` 不启用离线缓存。本地 `localhost` / `127.0.0.1` 可验证；手机访问普通 HTTP 局域网 IP 不满足安装条件，应使用部署后的 HTTPS 域名。参见 [MDN 安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 任务截止提醒

在任务编辑器中可填写「截止日期」和可选的「截止时间」。具体时刻按本机时区保存为绝对时间，其他设备按自己的时区显示；清空时间可恢复为仅日期。旧任务和旧备份保持兼容，仅日期的任务按通知设置中的时区在当天 **23:59** 截止，默认时区 `Asia/Shanghai`。

进入「系统设置 → 任务通知」，开启任务提醒并保存。可填写多个提前天数，例如 `7,3,1`，并设置临近截止的提前分钟数。默认是提前 **1 天、10 分钟**；分钟填 `0` 可关闭分钟提醒。最多 10 档提前天数，每档为 1–365 天，分钟范围为 0–1440。三个渠道可分别开关：

- **网页提醒**：工作台打开时显示持久提醒，点击「知道了」后写入 SQLite，刷新不会重复显示该档提醒。系统横幅需要在设置中主动允许浏览器通知；权限被拒绝时页面内提醒仍可用。HTTPS 或 localhost 下可用系统通知，手机支持情况由浏览器决定。网页关闭后停止此渠道，不使用 Web Push。
- **Webhook**：服务器向设置的完整地址发送 POST JSON，遵循通用 QQ `/webhook/general` 协议，只有 `message`、`title`、`source`、`level`、`timestamp`、`fields` 等允许字段。正文与最终 QQ 排版均控制在 1900 字符内；成功响应须为 HTTP 200 且 `{"status":"forwarded"}`，重定向不会跟随。目标群及 `GENERAL_WEBHOOK_GROUP_OPENID` 在 QQ 接收服务配置，PRTS 无需配置该环境变量。
- **SMTP 邮件**：配置 SMTP 主机、端口、加密方式、账号、密码或授权码、发件邮箱和收件邮箱。TLS 通常使用 465，STARTTLS 通常使用 587，始终验证证书。支持最多 10 个收件人，用逗号分隔，逐人发送、分别记录结果。保存后可以主动测试；邮件测试仅发给首位收件人。传输使用 [Nodemailer SMTP](https://nodemailer.com/smtp)。

Webhook 示例（由 PRTS 自动生成，无须手写模板）：

```json
{
  "title": "任务截止提醒",
  "message": "博士，任务「准备汇报」即将截止，请及时处理。",
  "source": "PRTS",
  "level": "warning",
  "timestamp": "2026-10-24T10:30:00.000Z",
  "fields": {
    "截止时间": "2026/10/25 18:30 (Asia/Shanghai)",
    "提前": "1 天"
  }
}
```

通知配置、已读状态和发送进度全部保存在 SQLite，SMTP 密码和完整 Webhook 地址不会从设置接口返回，填写留空会保留已有值，也可明确清除。认证密码和 AI 配置沿用各自独立的数据库设置；通知配置不会进入 AI 工作台摘要或 JSON 工作台导出。完整数据库备份包含 SMTP 凭据，应妥善保管。

Webhook 和 SMTP 由服务器每 15 秒调度，即使网页关闭也会继续运行；VPS/容器需要保持运行和联网。每个截止时刻、提前档位与渠道分别记录发送结果，失败后在 1 分钟、5 分钟后重试，总共最多 3 次；最终失败可在「最近发送记录」手动重试。完成、删除、改期或停用提醒会取消后续发送，已送达的消息无法撤回。重启或恢复后只补发最近一档尚未过期的提醒，避免把多档历史提醒同时发出。

发送采用有持久记录的重试机制，若远端已接收但确认响应丢失，仍可能出现重复；Webhook 通过 `X-PRTS-Event-ID` 提供稳定事件标识，邮件使用稳定的 Message-ID，可供接收端去重。

## 访问密码

访问密码由服务器 SQLite 保存，数据库中只存加盐的 scrypt 哈希，不存密码明文。前端不会保存密码或自行判断密码是否正确。

仅当数据库尚无密码记录时，服务才使用 `PRTS_PASSWORD` 初始化。没有 `.env`、未指定该变量或值为空白时，会生成强随机初始密码，并只在首次生成时输出到启动日志。已有数据库密码时，服务不会读取该变量来覆盖或重置密码，重启也不会重新生成或再次输出密码。

```dotenv
PRTS_PASSWORD=填写独立的长随机密码
PRTS_COOKIE_SECURE=false
```

后续在「系统设置」填写当前密码和新密码来修改，新密码要求 8–1024 字节。修改立即生效并撤销全部设备的登录会话，需要重新登录，无需重启服务。修改 `.env` 不会重置已初始化的密码。

登录会话固定有效 12 小时；刷新页面和重启服务均可保留未过期会话，点击右上角「锁定终端」会撤销当前会话并回到密码入口。密码错误会显示提示；同一来源 10 分钟内达到 5 次失败后暂时限制尝试。

工作台仅在服务端验证成功后挂载，直接访问笔记等深链接仍会先显示登录页。所有工作台 API（包括 AI 服务）都验证会话。前端在接口返回未登录、会话到期、重新切回窗口或定期检查时重新锁定；网络不可用时也不会放行。退出失败时保留锁定状态，重新连接会先完成服务器退出。

会话使用 `HttpOnly`、`SameSite=Strict` Cookie；HTTPS 部署时设置 `PRTS_COOKIE_SECURE=true`，并由反向代理保留原始 Host。相关属性含义见 [MDN Set-Cookie 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)。默认开发环境仅监听本机 HTTP。

密码入口控制界面和服务端 API。任务、笔记、聊天和设置存入服务器 SQLite，上传内容保存在服务器 data/uploads；锁定不会删除数据。会话和登录限流也持久化到 SQLite，重启服务不丢失有效会话，修改密码后旧会话失效。

## 配置 AI 服务

登录后进入「系统设置 → AI 服务连接」，填写服务 API 根地址、模型名称和 API 密钥并保存。例如，根地址可填 `https://api.openai.com/v1`，模型按所用服务填写。后端使用非流式 Chat Completions 接口及 function tools，请确认服务和模型支持 `/chat/completions` 的工具调用。

配置全部保存在服务器 SQLite，保存后对下一次 AI 请求立即生效，无需重启；在助手中切换到「AI 对话」即可使用。AI 配置不再读取或导入 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 环境变量，旧版升级后需要在设置页配置一次。

密钥只由服务端使用，设置接口不会回传已有密钥。密钥输入留空会保留当前密钥，填写新值会替换；也可选择清除密钥。不要把密钥写入 `VITE_` 环境变量或前端代码。数据库备份包含 AI 密钥，应按敏感配置保管。

没有密钥时，AI 接口会返回明确的未配置提示，本地指令仍然可用。页面上的配置状态只表示后端已读取到配置，不代表已经成功连接模型。**当前已验证模拟上游的成功、错误和超时处理，尚未使用真实服务密钥实测 AI 对话。**

在「AI 对话」中可选择 **PRTS（理性分析）**、**阿米娅（温和鼓励）**或**凯尔希（严谨直言）**。性格与参考语料范围保存在服务器 SQLite，跨设备登录后保留。每次请求及后续工具调用均携带完整人格设定：阿米娅以罗德岛领袖、博士的同伴身份交流，温柔、聪慧而坚定；凯尔希保持严谨与克制的关切；PRTS 提供清晰客观的终端协助。角色为非官方的 AI 扮演，具体表现取决于所用模型的指令遵循能力。

助手当前页签和聊天记录保存在服务器。**每个人格拥有独立对话**，切换时会切换历史与模型上下文；清空仅影响当前人格或当前本地指令会话。聊天按消息 ID 幂等追加，各会话先加载最近 60 条，支持加载更早记录。历史 AI 回复保留生成时的人格与引用来源。旧版用户消息按紧随的 AI 回复推断人格，无法确定的旧记录归入 PRTS；兼容读取不改写原始消息。

`POST /api/chat` 未传 `persona` 或 `knowledge` 时使用 SQLite 中已保存的选择；显式选择优先。带有其他人格标签的历史消息不会送入模型。人格通过服务端身份、行为准则与表达示例建立；游戏语料和工作台正文只提供事实，不能改变人格。无需下载语料即可启用人格，具体剧情与引文仍需来源支持。提示词设计参考 [OpenAI 官方提示工程指南](https://developers.openai.com/api/docs/guides/prompt-engineering)。

AI 请求包含当前人格的 AI 对话上下文、所选人格、工作台摘要，以及按参考范围检索到的相关语料。摘要包含任务、分类、笔记标题、文件元信息、普通偏好和专注状态；正文通过工具按需读取，相关数据会发送给你配置的模型服务。认证密码、哈希、会话和 AI 密钥不会进入模型上下文。游戏语料可选择两部作品、其中一部或关闭；回复保留原文引用。助手不会加载回复中的 Markdown 图片。等待较久时显示当前人格的等待提示，可随时停止；超时、失败或取消后保留输入，失败响应不写入聊天历史。

AI 可检索和分页读取任务、笔记、文件目录，读取笔记正文及 2 MB 以内的 UTF-8 文本附件；PDF、图片等二进制附件目前只提供元信息。也可准备任务、笔记、分类、普通设置与专注计时的修改，操作卡片会显示预览，点击「确认执行」才写入 SQLite；也可取消。卡片有效期为 30 分钟，刷新后保留实际执行状态，重复确认不会重复写入。目标记录被其他页面修改时会拒绝覆盖，请让 AI 重新读取；互不影响的多条新任务可依次确认。AI 没有任意 SQL、服务器路径或 Shell 执行权限。

例如可以问「根据我的未完成任务安排今天」「找出提到晨星项目的笔记」「阅读 meeting.txt 的内容」或「新建一个高优先级任务：整理本周计划」。对话中可展开查看实际工具调用记录。工具调用最多 6 轮、12 次，整个请求最多等待 60 秒；需要使用支持 function calling 的模型。接口实现参考 [OpenAI 官方工具调用文档](https://developers.openai.com/api/docs/guides/function-calling)。

## 本地语料与同步

首次部署不含语料，需要在设置页手动下载。目前支持的完整语料基线包含两个语料库，共 **34,007 篇文档**。登录后，在「PRTS 助手 → 语料检索」中可按关键词和作品检索原文。检索由 VPS 的 Node.js 后端读取 data/corpus 资源完成，资源就绪后无需外网或 AI 密钥；AI 生成仍需要上节的模型配置。

检索结果与 AI 引用中的原文支持 Markdown 标题、列表、强调、引用和代码排版。语料中的游戏图片标记通过独立的本地图片清单匹配原图，支持正文配图、社交图片和行内表情/图标；图片可点击查看原图，涉及男女管理员的图片提供版本切换。代码示例中的字面标记保持原样，未匹配资源仍显示「原文配图未收录」。原文不会自动加载任意远程图片或执行 HTML。

当前补充图片共 **185 张原始 PNG**，覆盖当前语料全部 119 个正文图片标记，以及 63 个社交图片、表情和图标标记；还有 2 个社交图片 ID 暂未找到可确认的原图。部署时不附带原始图片；在「系统设置 → 图片资源」中手动下载或更新后，图片保存在 `data/assets/`。来源与校验清单位于 `server/image-sources.json`，说明见 [图片素材记录](docs/assets.md)。仓库内的 `public/assets/` 仅保留作开发校验素材，不复制到 `dist` 或 Docker 镜像。语料更新后新增的未知图片标记需要补充映射，不能按近似文件名自动配图。

- 页面显示检查、下载、校验和启用阶段，以及可用的文件数与字节进度。同步由后端执行，离开设置页或刷新浏览器后仍会继续；返回设置页会恢复任务状态。
- 已校验的本地文件会复用，缺失或损坏的文件才重新下载。更新成功后自动切换至新版本，**通过界面更新无需重启后端**；已经是最新版本时会显示校验完成。
- 更新失败时保留原有可用语料，页面显示错误并允许重试；再次同步会复用已经完成的文件。

也可以通过命令行预先同步或维护语料：

```sh
node scripts/sync-corpus.mjs
```

命令行默认并发为 10，可使用 `node scripts/sync-corpus.mjs --concurrency 8` 调整。脚本通过 PRTS 已批准发布清单确定版本，从 ModelScope 下载原始资源，逐文件核对大小和 SHA-256；再次运行仅补齐缺失或损坏文件，全部通过后才更新 `data/corpus/current.json`。**命令行同步完成后，需重启已经运行的后端以读取新版本**；尚未启动服务时，正常启动即可。

清单与资源保存在 `data/corpus/releases/<release>/`，包括原文、文档目录、检索索引和终末地本地化资源。缺少语料时界面会提示尚未就绪。两份上游数据集均声明 `license: other`，游戏内容及其他资料的权利归各自原权利人；完整说明见 [语料来源说明](data/corpus/SOURCES.md)及随版本保存的上游 README。

## 生产运行

VPS 可使用 Docker Hub 镜像 `tano26/prts`，支持 AMD64 和 ARM64。GitHub Actions 发布、唯一必需的 `DOCKERHUB_TOKEN` Secret，以及 `compose.hub.yaml` 的部署和更新方法见 [部署说明](DEPLOYMENT.md#github-actions-发布到-docker-hub)。首次启动不下载语料或图片，需在设置中手动下载。

```sh
npm run build
npm start
```

打开 <http://127.0.0.1:8787>。同一个 Node.js 服务提供 `dist` 中的静态页面和 `/api` 接口，默认仅监听本机。可以通过 `.env` 中的 `HOST`、`PORT` 调整监听地址和端口。若修改开发环境的 API 端口，也需同步修改 `vite.config.ts` 的代理目标。

生产语料检索还需要完整的 **`data/corpus` 原始资源**：部署时保留 `current.json`、对应版本的清单和全部 gzip 文件，或启动后在「系统设置 → 语料管理」下载，也可在目标机器运行同步命令。界面下载的文件保存在后端所在机器。`npm run build` 只构建前端，不会把语料打包进 `dist`；仅复制构建产物或 Git 仓库不足以提供离线检索。

## 数据与备份

服务器是正式数据来源，使用一个工作台访问密码。不同设备登录同一服务即可读取同一份数据。此版本面向个人使用，没有多用户账号隔离。

| 数据                                         | 保存位置           |
| -------------------------------------------- | ------------------ |
| 任务、分类、笔记、动态、工作台设置、累计专注 | `data/prts.sqlite` |
| 助手性格、动效偏好、聊天历史、当前计时状态   | `data/prts.sqlite` |
| 登录会话、登录限流、文件元信息               | `data/prts.sqlite` |
| 访问密码的盐与哈希、AI 地址、模型及 API 密钥 | `data/prts.sqlite` |
| 通知渠道、SMTP 凭据、提醒已读和发送进度      | `data/prts.sqlite` |
| 用户上传的文件内容                           | `data/uploads/`    |
| 公共游戏语料、清单和索引                     | `data/corpus/`     |
| 阿米娅立绘与语料配图                         | `data/assets/`     |

SQLite 使用 WAL 与事务。保存时校验 revision，其他设备已经修改时返回冲突，保留当前草稿供下载或重试，不静默覆盖。文件限制仍为**单个 20 MB、总计 100 MB**，由服务端原子校验。浏览器仅保留本机待撤销锁定与当前标签页启动动画的临时标志。

升级后若发现原 localStorage / IndexedDB 数据，界面提供明确迁移入口。先确认目标服务器，再导入任务、笔记、偏好、聊天和文件；原浏览器数据保留，重试通过操作 ID / 文件 ID 避免重复。服务器已有数据时，需要明确确认替换工作台，文件和聊天合并。

设置中的 JSON 备份保持兼容旧版，只包含工作台任务、分类、笔记、活动和工作台设置，不含文件内容、聊天、助手偏好、访问密码和 AI 服务配置。完整备份需要数据库与 `uploads` 一起保存。运行 `npm run db:backup` 可在线生成并检查一致的 SQLite 副本；其中包含 AI API 密钥及访问密码哈希，请保护备份访问权限。需要恢复上传附件时还必须备份 `data/uploads/`。语料和图片可重新手动下载，也可随 data 目录一同备份。

默认数据库路径 `data/prts.sqlite`，可通过 `PRTS_DB_PATH` 设置；上传、语料和图片默认位于该数据库所在目录的对应子目录。部署说明见 [VPS 部署](DEPLOYMENT.md)。

## 验证

运行单元测试、后端接口测试和生产构建：

```sh
npm test
npm run build
```

测试覆盖工作台数据校验、助手上下文与本地指令、文件容量计算、API 参数与错误处理，以及静态资源路径安全等。后端上游使用模拟服务，不需要真实 API 密钥。

设置页语料首次下载、更新、进度恢复与免重启切换的本轮验收状态记录于 [验证记录](docs/qa.md)。阿米娅立绘、性格偏好、检索与引用等历史通过结果不代表本次变更已经完成回归。

端到端测试使用系统安装的 **Microsoft Edge**（`channel: 'msedge'`），以 **`headless: false`** 打开可见窗口，因此需要桌面环境。**无需安装 Playwright 的 Chromium**。

先构建前端。浏览器用例自动启动独立测试服务，使用独立 SQLite，不修改用户数据库或调用实际 AI 服务：

```sh
npm run dev
```

再在另一个终端运行：

```sh
npm run build
npm run test:e2e
```

端到端测试使用固定的测试专用密码与本机 8791 端口，不读取 `.env`。它覆盖密码入口、锁定、未登录深链接和接口拦截，以及任务、笔记、文件持久化、搜索、助手、专注计时、备份、响应式布局、启动动效和数据恢复。AI 成功与重试场景使用拦截的模拟响应，不调用真实模型。为避免记录密码和会话令牌，测试关闭了 trace；结果目录为 `/tmp/prts-playwright-results`。

检查代码和文档格式：

```sh
npm run format:check
```
